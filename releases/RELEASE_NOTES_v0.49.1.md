# Workspai VS Code v0.49.1

Release date: November 3, 2026.

This release is validated against Workspai CLI 0.80.0.

## Create in the intended destination

Create resolves an explicit request for a separate workspace or a project in the
active workspace before planning and approval. The target selector provides the
default when the destination is unspecified. The reviewed plan, selector, and
saved creation history stay aligned.

After scaffolding, **Continue in Agent** carries the actual destination, original
request, and selected model into a fresh Assistant conversation. A single created
project retains project scope; multiple projects retain workspace scope. Unrelated
repair context and editor issues are not carried over. Non-native stacks can also
continue in Agent with the appropriate available tools.

Creation receipts now say **Scaffold created**. Create establishes the synchronized
foundation; it does not claim that product implementation, build, or tests are
complete. Agent can continue implementation and run applicable project checks.

## A smaller, more consistent chat surface

- Creation history opens beneath the header, using the same searchable picker as
  Assistant. Search, keyboard navigation, Escape, and focus restoration are
  available without covering the composer.
- Active creations remain protected against deletion.
- Reviewed creation plans collapse while pending plans remain open for approval.
- Live progress follows the latest message while preserving manual scrolling.
- Chat spacing is more compact; right-to-left lists and long plan values stay
  within their message, and wide tables scroll independently.

## Change totals you can reconcile

Activity headers and file review use the same owned-transaction accounting.
Unrelated changes seen during inspection are not attributed to the Assistant;
rolled-back transactions are withdrawn even when the rollback receipt omits file
details. Headers also display added and removed line totals.

Text files appear before binaries in review. Binary files remain in the file count
and are labeled separately; they are excluded from line totals. Completed requests
are no longer marked as needing attention solely because earlier tool attempts
failed. Those attempts remain visible in activity history.

## More useful recovery

- An incomplete source checkpoint prevents command execution and returns a
  recoverable result. The Assistant can reassess scope instead of ending the
  session or weakening checkpoint coverage.
- Command receipts distinguish a command that never started from a failed process.
- Python-generated bytecode in `__pycache__` no longer causes false source-mutation
  failures during ordinary tests. Actual source in that directory stays protected.
- Creation errors identify filesystem space exhaustion and the failed phase.
  Partial work still requires inspection before retrying.
- Auto model native tool-result routing can use the existing JSON transport on
  the same model with the full tool catalog. Permission, quota, authentication,
  and unrelated errors do not use this compatibility fallback.
- Project-name validation and natural-language starter-kit lookup provide more
  useful guidance.

## Compatibility

- VS Code 1.106.0 or newer.
- Workspai CLI 0.80.0 or newer; verified runtime: 0.80.0.
- The extension downloads and integrity-checks its pinned official runtime on
  first use, then reuses its cache offline. A global CLI installation is optional.
- Model, tool, language-runtime, network, and host availability affect individual
  capabilities. Sufficient filesystem space is required for scaffolding.
- Create requires approval before mutation. Stopping AI planning is supported;
  cancellation of an in-progress CLI creation transaction remains limited.

For optional terminal use outside extension-owned operations:

```bash
npm install -g workspai@0.80.0
```
